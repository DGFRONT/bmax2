# Полный гайд по проекту «Сервисы региона» (бот + мини-приложение MAX)

Документ объясняет, из чего состоит проект, как он работает, куда уходят запросы,
где лежат данные и что делать в типовых ситуациях. Вместо реального домена и IP
используются обозначения `<ДОМЕН>` и `<ВНЕШНИЙ_IP>`.

---

## 1. Что это за система

Проект — одна программа на Go (`bmax`), которая одновременно делает три вещи:

1. **Отвечает в чате бота MAX.** Когда человек нажимает «Начать» или пишет боту,
   программа присылает приветствие с кнопкой «Открыть».
2. **Отдаёт мини-приложение.** Это веб-страница, которую MAX открывает внутри себя
   по кнопке «Открыть»: телефон, десктоп, веб-версия MAX.
3. **Хранит каталог** (категории, организации, аватарки, статистику) в базе SQLite
   и отдаёт его мини-приложению через API.

Рядом работает **Caddy** — веб-сервер, который принимает HTTPS-запросы из интернета,
сам получает и продлевает сертификат Let's Encrypt и передаёт запросы в `bmax`.

Обе программы запускаются в Docker-контейнерах одной командой `docker compose up -d`.

## 2. Схема: кто с кем общается

```
                              ИНТЕРНЕТ
   ┌──────────────────────┐                     ┌───────────────────────────┐
   │ Пользователь в MAX   │                     │ Серверы MAX               │
   │ (телефон/ПК/веб)     │                     │ platform-api.max.ru       │
   └──────────┬───────────┘                     └─────────────▲─────────────┘
              │ HTTPS 443: страница, API, картинки            │ HTTPS (исходящие:
              ▼                                               │ получение сообщений
   ┌──────────────────────┐                                   │ и отправка ответов)
   │ Роутер <ВНЕШНИЙ_IP>  │  проброс портов TCP 80/443,       │
   │                      │  UDP 443 → 192.168.1.39           │
   └──────────┬───────────┘                                   │
              ▼                                               │
   ┌───────────────────────────── Сервер server1 ─────────────┼──────────────┐
   │  Docker                                                  │              │
   │  ┌────────────────────┐   http:8080   ┌──────────────────┴───────────┐  │
   │  │ caddy              │ ────────────▶ │ app (bmax)                    │  │
   │  │ порты 80, 443      │               │ • веб-сервер мини-приложения  │  │
   │  │ HTTPS-сертификат   │               │ • API каталога                │  │
   │  │ том caddy-data     │               │ • бот (опрос MAX Bot API)     │  │
   │  └────────────────────┘               │ • база SQLite /data/bmax.db   │  │
   │                                       │   (том app-data)              │  │
   │                                       └───────────────────────────────┘  │
   └──────────────────────────────────────────────────────────────────────────┘
```

**Входящие соединения** (из интернета на сервер): только порты 80 и 443.
Порт 80 нужен Let's Encrypt для выдачи сертификата и для перенаправления на HTTPS.

**Исходящие соединения** (с сервера в интернет):
- `bmax` → `platform-api.max.ru` — бот забирает новые сообщения и отправляет приветствия;
- `caddy` → Let's Encrypt — получение и продление сертификата.

Браузер пользователя дополнительно загружает библиотеку MAX Bridge с `st.max.ru`.

## 3. Путь пользователя по шагам

### Шаг 1. Человек открывает бота в MAX
1. Нажимает «Начать» или пишет любое сообщение в личном чате.
2. MAX кладёт событие (`bot_started` или `message_created`) в очередь бота.
3. `bmax` постоянно опрашивает эту очередь (`GET /updates` — «long polling», запрос
   висит до 30 секунд, пока не появится событие). Поэтому для бота не нужны
   открытые порты и webhook.
4. `bmax` отправляет приветствие (`POST /messages`) с кнопкой «Открыть» типа `open_app`.
   В групповых чатах бот молчит.

Текст приветствия: `internal/bot/welcome.go`.

### Шаг 2. Человек нажимает «Открыть»
1. MAX открывает адрес мини-приложения `https://<ДОМЕН>/` (указан в настройках бота
   на платформе MAX для партнёров).
2. Запрос идёт: телефон → роутер (порт 443) → Caddy → `bmax`, который отдаёт `index.html`, CSS и JS.
3. Страница подключает библиотеку MAX Bridge (`https://st.max.ru/js/max-web-app.js`),
   она создаёт объект `window.WebApp`.
4. В `WebApp.initData` MAX кладёт **подписанную** строку: кто пользователь, когда
   открыл, параметр запуска. Подпись делается токеном бота, поэтому подделать её нельзя.

### Шаг 3. Загрузка каталога
1. Страница вызывает `GET /api/v1/catalog` и передаёт initData в заголовке `X-Max-Init-Data`.
2. `bmax` проверяет подпись (HMAC-SHA256 с ключом из `BOT_TOKEN`) и возраст
   (не старше `INIT_DATA_TTL`, по умолчанию 1 час). Если подпись неверна — ответ 401.
3. Каталог отдаётся **из памяти** (готовый JSON, собранный из базы при старте и после
   каждого изменения). База на каждый запрос не дёргается.
4. Параллельно `POST /api/v1/session` записывает в таблицу `app_users`, кто открыл
   приложение (для статистики).

### Шаг 4. Человек нажимает на организацию
- Ссылка на `max.ru` (канал, чат, бот) открывается **внутри MAX** через `WebApp.openMaxLink`.
- Любая другая ссылка (карта топлива, расписание транспорта) открывается **в браузере**
  через `WebApp.openLink`.
- Аватарки грузятся по адресу `/media/<имя файла>?v=<версия>`. Браузер кеширует их
  навсегда, а при замене картинки меняется `?v=`, поэтому все сразу видят новую.

## 5. База данных

**Тип:** SQLite — один файл, отдельный сервер базы не нужен.
**Где лежит:** внутри контейнера `/data/bmax.db`, физически — в Docker-томе `bmax2_app-data`
(на диске сервера обычно `/var/lib/docker/volumes/bmax2_app-data/_data/`).
Том переживает перезапуски и пересборки. Удаляется только явной командой
`docker compose down -v` — **не выполняйте её**, если не хотите стереть базу.

**Первое заполнение:** при старте, если база пустая, `bmax` импортирует папку `seed/`.
Дальше `seed/` не используется — правда живёт в базе.

**Схема** (`internal/store/migrations/0001_init.sql`):

```
categories                         organizations
┌────────────────────────┐         ┌────────────────────────────┐
│ id          (ключ)     │◀──┐ ┌──▶│ id          (ключ)          │
│ title                  │   │ │   │ name                        │
│ icon        эмодзи     │   │ │   │ url         уникальная      │
│ wide        1/0        │   │ │   │ icon        эмодзи          │
│ link ──────────────────┼───┼─┘   │ avatar ─────────────┐       │
│ group_titles JSON      │   │     │ group_name          │       │
│ position    порядок    │   │     │ updated_at          │       │
│ updated_at             │   │     └─────────▲───────────┼───────┘
└────────────────────────┘   │               │           │
                             │               │           ▼
organization_categories      │     featured             media
┌────────────────────────┐   │     ┌──────────────────┐ ┌─────────────────────┐
│ organization_id ───────┼───┼────▶│ organization_id  │ │ name   (ключ)       │
│ category_id ───────────┼───┘     │ position         │ │ content_type        │
│ position (0 = главная) │         └──────────────────┘ │ data   (картинка)   │
└────────────────────────┘                              │ sha256 (версия)     │
                                                        └─────────────────────┘
app_users                          schema_migrations
┌────────────────────────┐         ┌──────────────────┐
│ id  (ID пользователя)  │         │ version          │ ← какие миграции применены
│ first_name, last_name  │         └──────────────────┘
│ username, language_code│
│ launches  (запусков)   │
│ last_start_param       │
│ first_seen_at          │
│ last_seen_at           │
└────────────────────────┘
```

| Таблица | Что хранит |
|---|---|
| `categories` | Плашки на главном экране. `wide=1` — на всю ширину, `0` — половинка (идут парами). `link` — организация, которую плашка открывает сразу (топливо, МФЦ, запись к врачу, Водоканал). `group_titles` — подзаголовки внутри (у «Органов власти»: Министерства / Комитеты / Службы и управления). `position` — порядок. |
| `organizations` | Каналы, чаты, боты, сайты. `url` уникален. `avatar` — имя картинки из `media` или пусто (тогда показывается эмодзи). `group_name` — под каким подзаголовком стоит. |
| `organization_categories` | Связь «организация ↔ категория». Одна организация может быть в нескольких категориях (например, бот МФЦ — в «Ботах» и на плашке «Чат-бот МФЦ»). Первая категория (`position=0`) пишется подписью в поиске. |
| `featured` | Верхняя лента «Официальные каналы» и её порядок. |
| `media` | Сами картинки (в базе, а не файлами) — поэтому бэкап базы = бэкап всего. |
| `app_users` | Кто открывал приложение и сколько раз. Записывается только после проверки подписи MAX. |
| `schema_migrations` | Служебная: номер версии схемы. |

Связи настроены так, что удаление организации автоматически убирает её из категорий
и ленты, а удаление картинки — из аватарок.

**Посмотреть базу руками** (только чтение, на сервере):
```sh
cd ~/bmax2
docker compose exec app /app/bmax backup /data/look.db     # консистентная копия
docker compose cp app:/data/look.db ./look.db
sudo apt install -y sqlite3
sqlite3 look.db "SELECT id, name, url FROM organizations ORDER BY name LIMIT 20;"
sqlite3 look.db "SELECT COUNT(*), SUM(launches) FROM app_users;"
```
Меняйте данные через импорт или админ-API, а не прямыми SQL-запросами: после прямой
правки приложение не узнает об изменениях до перезапуска.

## 6. Настройки (`.env`)

Файл `.env` лежит **только на сервере** в `~/bmax2/.env`, в git он не попадает.
Формат: `ИМЯ=значение`, без пробелов вокруг `=` и без кавычек.

| Переменная | Обязательна | Что это |
|---|---|---|
| `DOMAIN` | да | Домен приложения. Caddy получает сертификат на него. |
| `ACME_EMAIL` | да | Почта для уведомлений Let's Encrypt. |
| `BOT_TOKEN` | да | Токен бота с платформы MAX для партнёров. Нужен для проверки подписи и для ответов в чате. **Держите в секрете.** |
| `BOT_POLLING` | нет (`true`) | `false` — выключить ответы в чате (если ботом управляет другой сервис через webhook). |
| `ADMIN_TOKEN` | нет | Включает админ-API. Не короче 32 символов: `openssl rand -hex 32`. |
| `INIT_DATA_TTL` | нет (`1h`) | Сколько живёт подпись MAX. |
| `LOG_LEVEL` | нет (`info`) | Подробность логов: `debug`, `info`, `warn`, `error`. |
| `BOT_API_URL` | нет | Адрес MAX Bot API, менять не нужно. |

После изменения `.env`: `docker compose up -d` (пересборка не нужна).

## 7. Как менять каталог

### Способ 1. Через файл (рекомендуется)
```sh
cd ~/bmax2
docker compose exec app /app/bmax export /data/export      # выгрузить текущее
docker compose cp app:/data/export ./export
nano export/catalog.json                                   # править
# картинки положить в export/media/ с именем <id организации>.jpg
docker compose cp ./export app:/data/export
docker compose exec app /app/bmax import /data/export      # загрузить
docker compose restart app                                 # показать изменения
```
Импорт проверяет файл целиком: если есть ошибка (неизвестная категория, повтор ссылки,
неверный id), ничего не меняется, а в ответ выводится, что именно не так.

### Формат `catalog.json`
```json
{
  "categories": [
    { "id": "doctor", "title": "Запись к врачу", "icon": "🩺", "wide": false,
      "link": "bot_minzdrav", "groups": [] }
  ],
  "organizations": [
    { "id": "minzdrav", "name": "Министерство здравоохранения РСО-Алания",
      "url": "https://max.ru/minzdravrso", "icon": "🏥", "avatar": "",
      "group": "Министерства", "categories": ["government"] }
  ],
  "featured": ["governor", "gov", "parlament", "mfc"]
}
```
- `id` — латиница в нижнем регистре, цифры, `_`, `-`.
- `url` — только `https://`. Ссылки `max.ru` откроются в MAX, остальные — в браузере.
- Половинки (`"wide": false`) должны идти парами, иначе одна останется без пары.
- Порядок плашек и ленты = порядок в массиве. Организации внутри категорий сортируются по алфавиту сами.

### Способ 2. Админ-API (без перезапуска)
Нужен `ADMIN_TOKEN` в `.env`. Команды выполняются на сервере:
```sh
T="Authorization: Bearer $(grep ADMIN_TOKEN ~/bmax2/.env | cut -d= -f2)"
H=https://<ДОМЕН>

curl -H "$T" $H/api/admin/stats                                  # статистика
curl -H "$T" -X PUT $H/api/admin/organizations/new_org -d '{
  "name":"Название","url":"https://max.ru/...","icon":"🏢","avatar":"","group":"","categories":["health"]}'
curl -H "$T" -X DELETE $H/api/admin/organizations/new_org
curl -H "$T" -X PUT --data-binary @logo.jpg $H/api/admin/media/new_org.jpg
```
Полный список адресов — в разделе 8.

## 8. Все адреса сервера (API)

| Адрес | Кто вызывает | Что делает |
|---|---|---|
| `GET /` , `/css/*`, `/js/*` | MAX при открытии | Страница мини-приложения |
| `GET /api/v1/catalog` | мини-приложение | Каталог. Требует `X-Max-Init-Data` |
| `POST /api/v1/session` | мини-приложение | Запись запуска в статистику. Требует `X-Max-Init-Data` |
| `GET /media/<имя>` | мини-приложение | Картинка-аватарка |
| `GET /healthz` | Docker, вы | Проверка, что сервер и база живы → `{"status":"ok"}` |
| `GET /api/admin/stats` | вы | Пользователи, запуски, активность за день/неделю/месяц |
| `GET` / `PUT /api/admin/catalog` | вы | Выгрузить / заменить весь каталог |
| `PUT` / `DELETE /api/admin/organizations/<id>` | вы | Добавить или изменить / удалить организацию |
| `PUT` / `DELETE /api/admin/categories/<id>` | вы | Добавить или изменить / удалить категорию |
| `PUT /api/admin/categories` | вы | Порядок категорий: `["fuel","mfc_bot",...]` |
| `PUT /api/admin/featured` | вы | Лента «Официальные каналы» |
| `PUT` / `DELETE /api/admin/media/<имя>` | вы | Загрузить / удалить картинку |

Админ-адреса работают только при заданном `ADMIN_TOKEN` и требуют заголовок
`Authorization: Bearer <ADMIN_TOKEN>`.

Внешние вызовы бота к MAX: `GET /me`, `GET /subscriptions`, `GET /updates`, `POST /messages`.

## 10. Ежедневные команды

Все команды — из папки `~/bmax2`.

| Задача | Команда |
|---|---|
| Состояние | `docker compose ps` |
| Логи приложения | `docker compose logs -f app` (выход `Ctrl+C`) |
| Логи HTTPS | `docker compose logs -f caddy` |
| Проверка изнутри | `curl -sk --resolve <ДОМЕН>:443:127.0.0.1 https://<ДОМЕН>/healthz` |
| Перезапуск | `docker compose restart` |
| Остановка (данные сохраняются) | `docker compose down` |
| Обновление кода с GitHub | `git pull && docker compose up -d --build` |
| Бэкап базы | `docker compose exec app /app/bmax backup /data/backup-$(date +%F).db` затем `docker compose cp app:/data/backup-$(date +%F).db .` |
| Кто открывал приложение | `docker compose logs app \| grep launch` |
| Кому бот отправил приветствие | `docker compose logs app \| grep "welcome sent"` |

### Что значат строки в логах `app`
| Сообщение | Значение |
|---|---|
| `listening` | Сервер запущен |
| `database seeded` | База была пустой и заполнена из `seed/` |
| `bot: polling updates` | Бот подключился к MAX и ждёт сообщений |
| `bot: welcome sent` | Приветствие отправлено |
| `bot: webhook subscriptions exist` | У бота настроен webhook, сообщения не придут — см. раздел 11 |
| `launch` | Кто-то открыл мини-приложение |
| `initData rejected` | Запрос без верной подписи MAX (не из MAX, или неверный `BOT_TOKEN`) |
| `admin auth failed` | Кто-то обратился к админ-API с неверным токеном |
| `error: BOT_TOKEN is required` | Не заполнен `.env` |

## 11. Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Сайт не открывается из интернета, изнутри `healthz` = ok | Роутер не пробрасывает порты | Проброс TCP 80, TCP 443, UDP 443 → `192.168.1.39`; удалённое управление роутером убрать с порта 443 |
| Браузер ругается на сертификат «NAGTECH» | Отвечает роутер, а не сервер | То же, что выше |
| Сертификат не выдаётся, в логах Caddy `challenge`/`timeout` | Let's Encrypt не может достучаться до порта 80 | Проверить проброс порта 80 |
| SSH перестал пускать (timeout) | Сменился IP сервера в сети, сбит проброс 22, или блокировка IP после неверных паролей | Закрепить `192.168.1.39` за сервером в DHCP роутера; проверить правило 22; подождать час |
| В приложении «Сессия устарела» | Подпись не прошла: неверный `BOT_TOKEN` или приложение долго было открыто | Проверить, что токен от того бота, к которому привязано приложение; перезапустить приложение в MAX |
| В приложении «Откройте приложение в MAX» | Страницу открыли в обычном браузере | Это нормально — каталог отдаётся только внутри MAX |
| Бот не отвечает в чате | Webhook у бота, `BOT_POLLING=false`, или нет исходящего доступа к `platform-api.max.ru` | Смотреть `docker compose logs app \| grep bot:` |
| Изменения в каталоге не видны | Импорт без перезапуска | `docker compose restart app` |
| `key cannot contain a space` | Ошибка формата `.env` | Убрать пробелы вокруг `=` |
| `permission denied ... docker.sock` | Пользователь не в группе docker | `sudo usermod -aG docker $USER`, перезайти |

## 12. Безопасность

- `BOT_TOKEN` и `ADMIN_TOKEN` не публикуйте и не пересылайте. Если токен «засветился» —
  перевыпустите его на платформе MAX, впишите в `.env`, выполните `docker compose up -d`.
- `.env` не коммитьте в git (он уже в `.gitignore`).
- Каталог отдаётся только запросам с действующей подписью MAX.
- Админ-API выключено, пока не задан `ADMIN_TOKEN`.
- Контейнер `app` работает без прав root, внутри нет оболочки и лишних программ.
- Делайте бэкап базы перед крупными изменениями каталога.

## 13. Как вносить изменения в код

1. Изменения готовятся в отдельной ветке на GitHub и оформляются pull request'ом.
2. Вы проверяете и нажимаете **Merge pull request** — код попадает в `main`.
3. На сервере: `cd ~/bmax2 && git pull && docker compose up -d --build`.
   База и сертификаты при этом сохраняются.
